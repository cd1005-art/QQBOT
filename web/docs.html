它是什么

QQBOT 是一个自托管的 QQ 官方机器人群管理控制台。它只做四件事：收事件、存证据、执行处置、留全痕。

  • 接入方式固定为 Webhook，用官方 Ed25519 验签
  • 不接第三方协议端，不模拟客户端，不做 AI 对话
  • 后端纯 Python 标准库（仅验签依赖 PyNaCl，老版本 Python 另需 tomli）
  • 前端原生 JS，无构建、无 CDN

快速开始

git clone https://github.com/cd1005-art/QQBOT.git
cd qqbot
python -m pip install -r requirements.txt
cp config.example.toml config.toml
python -m qqbot serve

访问 http://127.0.0.1:18901/panel/。若 app_id / app_secret / 面板密码任一为空，会自动进入初始化引导页。

离线自检（不联网、不需凭证）：

python tests/smoke.py

项值
接入方式Webhook
回调地址https://你的域名/qqbot/webhook

保存回调地址的瞬间平台就会发 op=13 校验请求。服务没起来、nginx 没反代、证书不对，都会导致保存失败。

nginx / systemd

站点需要三段：webhook 反代、面板 API 反代、面板静态。参考 deploy/nginx-qqbot-webhook.conf：

location ^~ /qqbot/webhook { proxy_pass http://127.0.0.1:18900; }

location ^~ /panel/api/    { proxy_pass http://127.0.0.1:18901; }

location ^~ /panel/ {
    root /www/wwwroot/你的域名;
    try_files $uri $uri/ /panel/index.html;
}

systemd：

sudo cp deploy/qqbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now qqbot
journalctl -u qqbot -f

Docker

docker compose up -d

或直接跑镜像：

docker run -d --name qqbot \
  -p 127.0.0.1:18900:18900 -p 127.0.0.1:18901:18901 \
  -v $PWD/data:/app/data -v $PWD/config.toml:/app/config.toml \
  qqbot:latest
容器内默认监听 0.0.0.0，宿主机端口绑定在 127.0.0.1，对外仍是 nginx 统一入口。

初始化引导

三项信息：AppID、AppSecret、面板密码。保存时直接写 config.toml 并热生效，不需要重启。

初始化完成后再访问 /panel/api/setup 会返回 403，避免被远程改写凭证。要改凭证请直接编辑配置文件。

规则与自动处置

匹配方式两种：contains（包含，忽略大小写）与 regex（正则，保存时校验语法）。动作五种：recall、mute、recall_mute、reply、recall_reply。

reply 与 recall_reply 用于关键词固定回复，回复走被动消息（带原 msg_id），受 5 分钟 / 5 次窗口限制；同一条消息命中回复规则后不再交给大模型，避免双重回复。

  • 同一条消息同一条规则只处置一次，平台重推不会重复禁言
  • 规则表 5 秒缓存，改完不用重启
  • 处置在独立线程执行，不占用 Webhook 的 3 秒响应窗口
  • 每次命中写 disposals，群管理 → 处置可查
  • 群详情页可单独关闭本群的自动处置
删除消息类规则前先想清楚：dry_run 关闭后，规则会真的撤回、真的禁言。建议先用「测试命中」验证正则。

定时任务

标准 5 段 cron：分 时 日 月 周，支持 *、*/n、a-b、a-b/n、枚举。

0 9 * * *       每天 09:00
*/30 * * * *    每 30 分钟
0 9 * * 1-5     工作日 09:00

调度线程每 20 秒扫一次到期任务，结果写入 last_result 与审计。目标群不选时等于库内全部群。

对话（大模型）

可选能力，默认关闭。任意 OpenAI 兼容接口都能接，填 base_url、api_key、model 三项即可。

配置说明
triggerat 仅 @机器人；all 所有消息（配合冷却，慎用）
keywords命中即回，不需要 @
context_turns每群携带最近几轮对话，控制 token
cooldown每群冷却秒数
daily_limit每群每天最多回复次数

回复走被动消息（带原 msg_id），受平台 5 分钟 / 5 次窗口限制；超窗口会失败并记入审计，不会退化成主动消息刷屏。

回复时 @ 提问者

群聊里 @ 某人只支持 markdown 消息。开启 [reply] at_user 后，回复会以 markdown 发送， 内容前缀 <qqbot-at-user id="member_openid" />；markdown 失败会自动退回纯文本。

对规则回复（reply / recall_reply）与模型对话同时生效，面板「设置 → 回复行为」可切换。

安全模型

  • dry_run 硬锁：开启时任何写操作只预览不执行，面板和 CLI 都受约束
  • 群白名单：allowed_groups 非空时只允许操作这些群
  • 会话：HMAC 签名的 Cookie，12 小时过期，密钥由 AppSecret 派生
  • 审计：每次写操作记录时间、动作、群、对象、结果

常见问题

保存回调地址失败
先在本机执行 curl http://127.0.0.1:18900/qqbot/webhook，不通就是服务或反代的问题。

事件表是空的
平台没切到 Webhook，或事件没勾选，或手机 QQ 里消息范围不是「全部」。

接口返回 11253
成员管理类接口需平台内邀，企业认证也不够，只能等官方开放。

面板打不开、域名解析异常
本地 DNS 缓存或污染，换 114.114.114.114 或执行 ipconfig /flushdns。

群消息收不到但事件正常
检查机器人是否为群管理员，以及群设置里的消息范围。
